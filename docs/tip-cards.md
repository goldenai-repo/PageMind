# Tip Cards — Design

Reader-anchored annotations that surface supplemental context for specific
passages in a book: background knowledge, controversies, deeper explanations,
cross-connections, and fact-checks. Tips sit alongside the reading experience
in a right-hand panel and never interrupt the flow of the text.

## Concept

A **tip card** is attached to a verbatim passage ("anchor") in a book. When a
reader opens a book, the tips for that book load into a collapsible panel. Tips
can be authored by the reader manually, or generated by Claude from the text on
the current page.

The 💡 lightbulb button in the header toggles the tips panel, mirroring the
existing 📑 TOC button. On narrow viewports the panel overlays the reading area
instead of splitting it.

### Tip card anatomy

```
┌─────────────────────────────────┐
│ ● BACKGROUND          AI · Ch2  │  ← type badge + source + anchor location
├─────────────────────────────────┤
│ Neo-Darwinian Synthesis         │  ← title
│                                 │
│ The "Modern Synthesis" of the   │  ← body (2–4 sentences)
│ 1930s–40s united Mendelian      │
│ genetics with Darwinian         │
│ natural selection...            │
│                                 │
│ 📎 Stanford Encyclopedia        │  ← optional references
└─────────────────────────────────┘
```

Clicking a card scrolls the reader to its anchored passage and briefly
highlights it.

### Type visual language

| Type          | Icon | Color            | Use when                                    |
| ------------- | ---- | ---------------- | ------------------------------------------- |
| `background`  | ●    | Blue `#2E86AB`   | Historical context, who/what something is   |
| `controversy` | ⚡   | Orange `#e68a2e` | Competing theories, academic disputes       |
| `deep-dive`   | ◈    | Purple `#7c3aed` | Richer explanation of a concept             |
| `connection`  | ⟷    | Green `#27a96c`  | Links to other books, fields, or ideas      |
| `fact-check`  | ✓    | Red `#dc2626`    | Verifying or qualifying a claim             |

## Data schema

```ts
// src/lib/tips.ts

export type TipType =
  | "background"
  | "controversy"
  | "deep-dive"
  | "connection"
  | "fact-check";

export type TipSource = "ai" | "user";

export type TipReference = {
  label: string;
  url: string;
};

export type TipAnchor = {
  // The verbatim passage in the book this tip refers to.
  // Used to locate and re-highlight the tip when re-opening the book.
  text: string;
  // Format-specific location for display grouping.
  chapterHref?: string; // EPUB: spine item href
  pageNumber?: number;  // PDF: 1-indexed
};

export type TipCard = {
  id: string;
  bookId: string;
  anchor: TipAnchor;
  type: TipType;
  title: string;
  body: string;
  references?: TipReference[];
  source: TipSource;
  createdAt: string; // ISO 8601
};
```

## Storage

Tips live in a new `tips` object store in the existing `pagemind` IndexedDB
database, alongside the current `books` store. A `bookId` index gives fast
per-book lookup.

```
pagemind DB
├── books   (existing)
└── tips    (new)  — keyPath: "id", index: "bookId"
```

Helper API in `src/lib/tips.ts`:

- `saveTip(tip: TipCard): Promise<void>`
- `loadTipsForBook(bookId: string): Promise<TipCard[]>`
- `deleteTip(id: string): Promise<void>`

## Architecture

```
User selects text
      │
      ▼
"Add tip" popover
      │
      ├─ type, title, body form ──────────────► saveTip → IndexedDB
      │
      └─ [AI mode] ──► POST /api/tips/generate
                             │
                             ▼
                       Claude API (claude-sonnet-4-6)
                       given anchor text + book title
                       → { type, title, body, references }
                             │
                             ▼
                       saveTip → IndexedDB → render in panel
```

## MVP build order

1. **Schema + IndexedDB** — `src/lib/tips.ts` with `saveTip`,
   `loadTipsForBook`, `deleteTip`.
2. **Tips panel** — right sidebar in `BookReader`, toggled by a lightbulb
   button in the header (mirrors the TOC button).
3. **Manual creation** — text selection triggers an "Add tip" popover with a
   type picker and title/body fields.
4. **AI generation** — a "Generate tips for this page" button that sends the
   current page text to Claude via `/api/tips/generate`.

## Open questions

- Should AI generation run per-page on demand, or pre-generate for the whole
  book on first open?
- Do tips sync per-user (server-side) or stay device-local in IndexedDB like
  books currently do?
- Should readers be able to edit AI-generated tips, or only accept/dismiss them?
